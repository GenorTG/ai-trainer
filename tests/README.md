# Test Suite — Finetune Studio + Inference Server

Comprehensive pytest suite covering every component of the Finetune Studio
training platform and the inference-server that serves its models.

## Layout

```
tests/
├── conftest.py              # Shared DRY fixtures (mock_engine, mock_rag_store, ...)
├── run_all.py               # Master runner — all suites at once
├── api/
│   ├── conftest.py          # API-specific overrides (chromadb/llama_cpp stub,
│   │                        #   TestClient setups for server.py + server_v2.py)
│   ├── test_finetune_studio.py
│   ├── test_inference_server.py
│   └── test_inference_server_v2.py
├── frontend/
│   ├── test_pages.py
│   ├── test_static.py       # JS / CSS / template asserts
│   └── test_cli_gui_coverage.py   # CLI→GUI matrix
├── unit/                    # Mock-heavy unit tests
│   ├── test_parsers.py
│   ├── test_rag.py
│   ├── test_samplers.py
│   ├── test_mcp.py
│   ├── test_templates_manager.py
│   ├── test_templates_renderer.py

│   ├── test_benchmarks.py

```

## How to Run

### Everything (one shot)

```bash
python tests/run_all.py
```

### Just one suite

```bash
python tests/run_all.py --suite unit      # unit tests (fast, mocked)
python tests/run_all.py --suite api       # FastAPI endpoint tests
python tests/run_all.py --suite frontend  # HTML/JS/static asset tests
```

### With coverage report

```bash
python tests/run_all.py --coverage
# open tests/coverage_html/index.html in a browser
```

### Pytest directly (if you want full control)

```bash
# Run only fast unit tests (skip @pytest.mark.slow)
python -m pytest tests/unit/ -m "not slow"

# Run a single file with verbose output
python -m pytest tests/api/test_finetune_studio.py -v

# Run a single test
python -m pytest tests/api/test_finetune_studio.py::TestTestingRouter::test_testing_chat_returns_response -v

# Stop on first failure
python -m pytest tests/ -x

# Match a pattern
python -m pytest tests/ -k "rag"
```

## Conventions

- **DRY** — every fixture lives in `conftest.py`; tests import and use them.
- **No real GGUF / models / network** — GGUF loader, llama.cpp, sentence-
  transformers, ChromaDB, GPU/CUDA are all stubbed. Tests run in ~30s
  end-to-end on a single CPU.
- **FastAPI TestClient** — endpoints are exercised through `TestClient`,
  no real server starts.
- **Markers** — `@pytest.mark.{unit,integration,api,frontend,slow}` —
  slow tests touch GPU/network paths even when mocked; skip them with
  `-m "not slow"` for fast feedback.
- **CLI → GUI matrix** — `tests/frontend/test_cli_gui_coverage.py`
  enforces that every CLI command has a GUI equivalent. Adding a new CLI
  command? Add an entry to `GUI_ROUTES` in that file and the route in
  `webui/routes/`.

## Adding a New Test

1. Pick the right directory: `tests/unit/` for pure logic, `tests/api/`
   for FastAPI endpoints, `tests/frontend/` for HTML/JS.
2. Reuse fixtures from `conftest.py` — don't re-mock the heavy stuff.
3. Mark slow tests with `@pytest.mark.slow`.
4. Run `python tests/run_all.py` and confirm everything still passes.

## Performance

The full suite (571 tests + 3 skipped) takes ~30 seconds on a single CPU.

| Suite       | Tests | Time  |
|-------------|-------|-------|
| unit        | ~430  | ~5s   |
| api         | ~75   | ~8s   |
| frontend    | ~30   | ~3s   |
| integration | ~36   | ~14s  |
